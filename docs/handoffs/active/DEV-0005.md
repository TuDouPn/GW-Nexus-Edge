## 0. 设计修订（一次确认通过，已并入实现）

1. **Fork SARIF 权限模型**：repository-security 拆分"扫描"与"上传"独立 Job——Fork PR 仅 `contents: read`、
   真实扫描、脱敏 Artifact、不授予 `security-events: write`、不上传 SARIF、发现问题 Job 失败；push main
   独立 Job 可单独授予 `security-events: write` 并上传 SARIF；**禁止用 `pull_request_target` 执行 PR 代码**、
   禁止用 event 表达式动态扩大整个 Workflow 权限。
2. **Required Check 稳定名称**：显式 Workflow name + Job name，分支保护用 Job Display Name 冻结
   `Backend CI / Verify`、`Repository Security / Scan`、`Workflow Security / Lint`、`Dependency Review / Review`；
   schedule/push-only/SARIF-upload-only Job 不得作为 PR Required；路径优化须保留同名 Required 汇总 Job。
3. **diff 检查**：checkout 获取足够 base/head 历史；PR 用 merge-base→head SHA 执行 `git diff --check`；
   push main 检查提交范围；工具运行后检查工作树未提交变更。
4. **安全工具供应链**：GitHub Action 固定 40 位 commit SHA + 注释版本；下载二进制固定版本 + 官方 SHA256/签名
   校验；禁 `curl|sh`；工具来源/版本/Action SHA/二进制校验进第三方清单；区分 Action 引用与二进制制品。
5. **真实扫描命令与阻断语义**：Secret Scan（工作树+历史，确认 Secret 阻断，输出不含值，基线忽略记录规则/
   原因/范围）；SCA = filesystem/dependency/SBOM scan（**非 Container Image Scan，NOT_APPLICABLE_YET**），
   HIGH/CRITICAL 默认阻断，例外版本化+原因+有效期，数据库不可得 → TOOL_BLOCKED/INFRASTRUCTURE_FAILURE；
   SBOM = CycloneDX 2.9.3，校验存在/可解析/含组件并作 Artifact；License = 从 Maven resolved tree/SBOM 取证，
   未识别/缺失/多表达式 → 人工复核，不确定法律结论 → REVIEW_REQUIRED。
6. **Apache-2.0 外部贡献规则**：CONTRIBUTING 明确"贡献即同意按 Apache-2.0 授权（inbound=outbound 基线，
   不等同 CLA/DCO）"；禁提交无权授权代码/企业资料/Secret/专有模板/受限数据；第三方代码说明来源与许可证；
   CLA/DCO/商标政策未决定，不擅自引入机器人或签署门禁。
7. **安全报告渠道**：优先启用并验证 GitHub Private Vulnerability Reporting；SECURITY.md 引导 Security
   Advisory 私密入口；平台不可用 → BLOCKED_BY_PLATFORM + 请求真实安全邮箱；禁止编造 security@/个人邮箱；
   CODE_OF_CONDUCT 执行联系可用仓库维护者 GitHub 账号（临时公开治理联系，非私密漏洞通道）。
8. **Branch Protection 顺序**：推 PR → 等 Required 候选 Job 真实成功 → 从 Check Runs 读准确 context → 配置
   main 保护 + Required Checks → 重新验证 → 平台不支持记录 HTTP + BLOCKED_BY_PLATFORM；禁止凭设计名称声称已启用。
9. **开源决策同步**：ADR-0010 直接 Accepted；全仓搜索"私有 GitHub/私有仓库/闭源/Proprietary/不开放源码/
   源码托管"；Accepted Blueprint 现行决策原子修正；历史 Handoff 标记"历史状态，已被 ADR-0010 取代"，不批量改写。
10. **状态边界**：G-06 需 PR CI 真实成功 + Fork 安全模型检查 + main 保护 + Required Checks 真实启用才 PASS；

### 3.2 GitHub Actions 工作流文件（`.github/workflows/`）

| 文件 | 触发 | 内容 |
|---|---|---|
| `backend-ci.yml` | `pull_request`（含 fork）+ `push` main | Ubuntu runner；Java 21；Maven Wrapper；Maven 依赖缓存；`backend/` 下 `./mvnw clean verify`；Testcontainers Docker 环境（Docker 服务）；`git diff --check`；测试报告归档（surefire-reports）；`timeout-minutes` 上限 |
| `repository-security.yml` | `pull_request` + `push` main + schedule（如允许） | Secret Scan（Gitleaks，固定版本）；SCA/容器漏洞（Trivy，固定版本）；CycloneDX SBOM（Maven 插件固定版本）；License 合规扫描；结果以 **SARIF/Artifact** 输出；**扫描失败与工具基础设施失败必须区分**（禁止"未执行却显示通过"）；工具与规则版本固定 |
| `dependency-review.yml` | `pull_request`（dependency-review 事件；权限允许时） | GitHub Dependency Review；不获取额外写权限 |
| `workflow-lint-security.yml` | `pull_request` + `push main` | `actionlint`（固定版本）校验 Workflow YAML；检查危险权限/可变 Action 引用/`pull_request_target`/Secret 暴露风险 |

### 3.3 权限矩阵（公开仓库最小权限）

- **默认 `permissions: contents: read`**（workflow 级 + Actions 设置）。
- `backend-ci`：`contents: read`（无需写）。
- `repository-security`：`contents: read`；SARIF 上传需要 `security-events: write`（仅当可配置时授予，
  否则以 Artifact 输出）；不读任何 Repository/Environment/组织 Secret。
- `dependency-review`：`contents: read` + `pull-requests: read`。
- `workflow-lint-security`：`contents: read`。
- **任何 Job 不得** push、发布 Package、签名、部署、发表评论或修改仓库。

### 3.4 Fork 威胁模型（公开仓库不可信代码）

- **禁止 `pull_request_target` 执行 PR 提供的代码**；不可信 PR 仅用 `pull_request` 事件（fork 上隔离环境）。
- Fork PR 工作流**不得读取** Repository/Environment/组织 Secret。
- 不得为获取 Secret 使用危险事件或检出并运行 Fork 代码。
- 真实 Provider（DEEPSEEK/OPENAI）、DM8、Renderer、部署、签名等需要 Secret/受控环境的测试
  **不得在不可信 PR 中执行**（标记 NOT_APPLICABLE_YET / BLOCKED）。
- **Actions 固定到不可变 commit SHA**（注释保留版本名称，如 `# actionlint v1.7.7`）；禁止 `@main/@master/可变 tag`。
- 第三方 Actions 进入供应链清单（THIRD-PARTY-NOTICES + SBOM）。

### 3.5 Required Checks 名称（实施后真实运行成功才设 Required）

- 候选：`backend-ci`、`repository-security`、`workflow-lint-security`（如可配置）。
- 仅将**真实存在且成功运行**的检查设为 Required；**未建立的未来 Gate 不写成 Required Check**。

### 3.6 扫描工具及固定版本策略

| 工具 | 版本策略 | 说明 |

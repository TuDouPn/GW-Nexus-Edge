## 2. 本次设计修订（相对初版必须落地的 10 项）

初版方向通过，但不得把“固定版本 + commit SHA”混成一条规则，不得把 G-07 在第三方未逐项核验时标 PASS，不得把 Job Display Name 写成 YAML 文件名，不得用 `pull_request_target` 或 workflow 级动态提权。

### 2.1 公开 Fork 的 SARIF 权限模型

`repository-security.yml` **必须拆分“扫描”和“上传”两个 Job**。禁止用 event 表达式动态扩大整个 Workflow 的 `permissions:`。高权限只允许出现在独立 Job，并用明确事件条件控制。

| 事件 | 扫描 Job（`Repository Security / Scan`） | 上传 Job（`Upload SARIF (main only)`） |
|---|---|---|
| `pull_request`（含 Fork） | 必须真实执行 Secret / SCA / 漏洞 / License 扫描；`permissions` **仅** `contents: read`；不读取任何 Repository / Environment / 组织 Secret（含不写 `env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}`）；生成脱敏 Artifact；**不**授予 `security-events: write`；**不**上传 SARIF 到 Code Scanning；发现阻断问题 Job **必须失败**；不得因为无法上传 SARIF 而跳过扫描或把扫描标绿 | 不运行（`if: github.event_name == 'push' && github.ref == 'refs/heads/main'`） |
| `push` `main`（可信） | 执行相同扫描与阻断语义 | 本 Job **单独**授予 `security-events: write` 并上传 SARIF |

- **禁止** `pull_request_target` 执行 PR 代码。
- Workflow 级 `permissions` 固定 `contents: read`。
- 上传 Job 失败不得回溯改变扫描 Job 的结论；扫描失败则上传 Job 因 `needs` 跳过，扫描失败仍是失败。

### 2.2 Required Check 稳定名称

必须显式设置 Workflow `name` 与 Job `name`。分支保护使用 **GitHub Check Run 的 Job Display Name**，不是 YAML 文件名。

冻结（Job `name:` 即为 Check Run context）：

| Workflow `name` | Job `name`（Required Check context） | 可否作为 PR Required Check |
|---|---|---|
| `Backend CI` | `Backend CI / Verify` | 是 |
| `Repository Security` | `Repository Security / Scan` | 是 |
| `Workflow Security` | `Workflow Security / Lint` | 是 |
| `Dependency Review` | `Dependency Review / Review` | 仅当该 Check 已在 PR 上真实成功后再纳入；本 PR 因依赖图 bootstrap 允许暂不 Required |
| `Repository Security` | `Upload SARIF (main only)` | **否**（push-only / SARIF-upload-only） |
| `Dependency Submission` | `Submit Maven Dependency Graph` | **否**（push-only） |

- 不得把 schedule-only、push-only、SARIF-upload-only Job 设为 PR Required Check。
- 本项不使用路径过滤；若未来使用，必须保留同名 Required Gate 汇总 Job，避免部分 PR 永久 Pending。
- 分支保护实施顺序见 §2.8：先等 Check Run 真实成功，再从 API 读取准确 context，再配置。禁止凭设计名称声称已启用。

### 2.3 diff 检查

PR **不得**只执行无参数 `git diff --check`。

1. `actions/checkout` 使用 `fetch-depth: 0`，并额外 fetch PR `base.sha` / `head.sha`（或 push 的 `before`/`after`）。
2. PR：`git diff --check $(git merge-base <base-sha> <head-sha>)..<head-sha>`。
3. push `main`：对 `github.event.before..github.sha` 检查提交范围；`before` 为全零（首推）时退化为 `HEAD^..HEAD`。
4. 工具运行后再执行工作树干净检查（`git status --porcelain` 非空则失败）。

本地提交前可用无参数 `git diff --check` 检查工作树；CI 必须按范围检查。

### 2.5 真实扫描命令与阻断语义

#### Secret Scan（Gitleaks 8.30.1 二进制）

```bash
gitleaks detect --source <repo> --redact --report-path gitleaks-git.json --exit-code 1
gitleaks detect --source <repo> --no-git --redact --report-path gitleaks-tree.json --exit-code 1
```

- 第一条扫描 Git 历史；第二条扫描当前工作树。
- `--redact`：输出不得包含 Secret Value。
- 任一命令退出码 1 = 确认 Secret = **阻断**。
- 不使用全局 ignore 掩盖问题。如需基线忽略，必须在版本化规则中记录规则、原因和范围（当前不设忽略）。

#### SCA / 漏洞（Trivy 0.74.0 filesystem/dependency scan）

**当前没有生产 OCI Image，禁止描述为 Container Image Scan。** Container Image Scan = `NOT_APPLICABLE_YET`。

```bash
trivy fs --scanners vuln --severity HIGH,CRITICAL --exit-code 1 \
  --format sarif --output trivy-fs.sarif .
```

- 扫描输入：仓库工作树（filesystem / 依赖清单，含 Maven POM）。
- 阈值：HIGH / CRITICAL 默认阻断（`--exit-code 1`）。
- 例外必须写入 `docs/dev-0005/scan-exceptions.json`：CVE、组件、版本、原因、有效期；当前为空。
- 若 Trivy 数据库无法获取或未产生可解析 SARIF：退出为 **TOOL_BLOCKED / INFRASTRUCTURE_FAILURE**，**不得**显示为无漏洞。
- Fork PR 只上传脱敏 SARIF Artifact，不调用 Code Scanning API。

#### SBOM（CycloneDX Maven Plugin **2.9.3**，已验证）

```bash
./mvnw -f backend/pom.xml org.cyclonedx:cyclonedx-maven-plugin:2.9.3:makeAggregateBom \
  -DoutputFormat=all -DoutputName=aggregate-bom
```

- 生成 `backend/target/aggregate-bom.json` 与 `backend/target/aggregate-bom.xml`。
- 校验：文件存在、JSON/XML 可解析、`components` 数量 > 0。禁止只检查命令退出码。
- 作为 CI Artifact 保存。

#### License

- 证据来源：Maven 已解析依赖闭包的 CycloneDX SBOM；SBOM 无许可证时读取本地 Maven 仓库中对应 POM 的 `<licenses>`（仍是 POM 证据，不是凭组件名称猜测）。
- 不得凭组件名称或二手表格猜测许可证。
- 未识别、缺失、多许可证表达式 **不得默认通过**，进入人工复核清单（`REVIEW_REQUIRED`）。
- License 政策涉及不明确法律结论（含 GPL、LGPL、EPL、CDDL、GPL+FOSS Exception、Public Domain、双许可）时标记 `REVIEW_REQUIRED`，不由 AI 自行解释为与 Apache-2.0 兼容。
- 明确的单一宽松许可证（Apache-2.0 / MIT / BSD-2-Clause / BSD-3-Clause / ISC / 0BSD / CC0-1.0 / EDL-1.0）且有 POM/SBOM 证据，记录为 `POLICY_ACCEPT`。
- CI 阻断：当前 SBOM 中出现 **未进入 baseline** 的新组件，或新的缺失许可证。已知 `REVIEW_REQUIRED` 项输出清单但不把“未完成核验”伪装成通过。
- **G-07 只有当前解析依赖完成逐项核验（`REVIEW_REQUIRED` 为空）后才能 PASS。** 本项若仍有待核验项，G-07 = **PARTIAL**。

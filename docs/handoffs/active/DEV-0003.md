## 0. 有条件批准修正（已同步，评审六大项）

### 0.1 修复 P0 跨 Scope 恢复问题
1. **修正设计稿错误**：Adapter 不得用原始 userId/sessionId 保存/读取 ExecutionContextState——必须与
   AgentScope 会话同一隔离域（scopedUserId/scopedSessionId）。
2. `startExecution` 先计算 `AgentRuntimeIdentityMapper.ScopedIdentity`，再用 scoped 身份保存运行期恢复投影。
3. `resume` 不凭 reference 的原始 userId/sessionId 推断 Tenant/Workspace。
4. **扩展领域契约**：`AgentExecutionReference` 明确携带 `tenantId/workspaceId/userId/sessionId`，
   全部 fail-closed 校验。
5. `resume` 依据这些字段重算 scoped identity，从 scoped Redis slot 读取状态。
6. 恢复状态逐项校验 `taskId/tenantId/workspaceId/userId/sessionId`——缺失/错绑/篡改/跨 Scope 一律失败。
7. 后续正式业务层只能基于 **MySQL 中已授权的 Task/TaskAttempt 数据**构造恢复请求，不得信任客户端提交的
   恢复 Scope；该约束写入 Port 注释与 ADR-0008。

### 0.2 修复 P0 会话误删除问题
1. **删除**"Task 终态后调用 `AgentStateStore.delete(userId, sessionId)`"的设计。
2. 该 API 是 **Session 级删除**（`delete(String, String)`），会删除整个会话状态，不能作单 Task 清理。
3. **实证**：`AgentStateStore.delete(userId, sessionId, stateKey)` 是接口 **no-op 默认方法**
   （javap 实证：`return` 不删除任何数据）；`RedisAgentStateStore` 只实现两参 Session 级 delete——
   **不得假设三参单状态键删除可用**。
4. DEV-0003 **不实现直接 EXPIRE AgentScope 内部键**，不自行解析/操作官方内部键。
5. Session 删除只允许：正式会话生命周期结束、无可恢复 Task、满足 Retention Policy 后，由
   **独立生命周期服务**调用官方 session delete——**该服务不属于本 Work Item**。
6. 测试 C-9 改为验证"**Task 完成不会误删共享 Session 状态**"；受控 Session delete 仅在显式会话
   生命周期操作中验证（C-10），**不接入 Task 终态自动清理**。

### 0.3 明确数据权威边界
1. `RedisAgentStateStore` 只作为 AgentScope Session/Agent State 的**运行时持久化机制**。
2. Nexus Task、TaskAttempt、版本、状态、恢复授权的**权威源长期属于 MySQL**。
3. `ExecutionContextState` 暂存 Redis 时定义为**运行期恢复投影与一致性校验副本**，不得称业务权威数据。
4. 不新增第二套 Agent 状态机，不自行实现 AgentScope Checkpoint。
5. Redis/模型异常时 Adapter 只抛**脱敏异常**并产生 **FAILED 执行事件**；不得声称已持久化业务 Task=FAILED。

### 0.4 纠正文档事实
1. **实证**：`normalizeUser` 仅处理 null/blank（源码：`userId == null || userId.isBlank() ? ANON_USER : userId`），
   **不净化路径字符**；键安全来自 Nexus scoped identity（base64url 路径安全）。
2. Redis 集成测试使用 `org.testcontainers:testcontainers` + `GenericContainer`；**删除"testcontainers-redis 模块"表述**。
3. **Jedis 7.4.1 与 Spring Boot 管理 Lettuce 7.5.2 均通过真实 Redis 组合测试后再决定生产客户端**；
   未经测试不提前冻结。
4. Provider Smoke 使用**独立 Maven Profile**；未提供凭证记录 `BLOCKED_BY_CREDENTIAL`，不将跳过写成通过证据。
5. 基线 HEAD 以实际 `git rev-parse HEAD` 为准（`8b79ecb`）。

## 3. 设计正文（修订版）

### 3.1 当前 AgentScope Adapter 职责
见 §0.1/§0.3。`stateStore` 注入官方 `AgentStateStore`；`ExecutionContextState` 为运行期恢复投影。

### 3.2 AgentScope 官方 Persistence/Recovery API 实证
- `agentscope-extensions-redis:2.0.1`（jedis 7.4.1 / redisson 4.2.0 / lettuce 6.4.2.RELEASE）；
- `RedisAgentStateStore implements AgentStateStore`（Builder: keyPrefix + jedis/lettuce/redisson）；
- 键结构 `{prefix}{userId}/{sessionId}:{key}`（含 `:list`/`:list:_hash`/`:_keys`），默认前缀
  `agentscope:session:`；`normalizeUser` 仅 null/blank（§0.4）；
- 官方实现**不设 TTL**；**三参 delete 为 no-op 默认方法，两参 delete 为 Session 级**（§0.2）；
- `DistributedStore`/`RedisDistributedStore`/`RedisSnapshotSpec`/`RedisRemoteSnapshotClient` 存在
  （沙箱快照/远程 FS，Coding 取向；V1 经营分析不引入）。

### 3.3 Nexus Task 与 AgentScope Execution 边界
四标识 taskId/taskAttemptId/agentId/traceId（ADR-0006）；scoped Runtime Identity（DEV-0002）；
`AgentExecutionReference` 扩展携带 tenantId/workspaceId/userId/sessionId（§0.1-4）。

### 3.4 Redis 键、Key Scope、TTL 与清理责任（修订版）
- 键布局：`{keyPrefix}{scopedUserId}/{scopedSessionId}:nexus_execution_context:{taskId}` 与
  `{keyPrefix}{scopedUserId}/{scopedSessionId}:agent_state`（**全部 scoped 分区**，§0.1-2）。
- keyPrefix：`nexus:{env}:agentscope-session:`，**env 必须校验（允许字符集）**（C-12）。
- **TTL/清理**：AgentScope 不设 TTL（实证）；**Nexus 不直接 EXPIRE/操作官方内部键**（§0.2-4）；
  Session 生命周期删除归独立生命周期服务（§0.2-5），本 Work Item 不实现终态自动清理。

### 3.5 调用链与恢复时序（修订版）
- start：算 scoped → `stateStore.save(scopedUser, scopedSession, storeKey(taskId), ExecutionContextState)` →
  建 HarnessAgent（scoped RuntimeContext）→ 执行。
- resume：reference 携带 tenantId/workspaceId/userId/sessionId → 重算 scoped → 从 scoped slot 读取 →
  逐项校验（taskId/tenantId/workspaceId/userId/sessionId）→ 一致则重建 Agent（同 scoped）→ attemptNo++。
- 时序不变量：先读+校验再建 Agent（失败不遗留未关闭 Agent）。

### 3.6 错误、幂等、并发与 fail-closed 规则
- Redis/模型异常 → 脱敏异常 + FAILED 执行事件（不伪装成功，不声称持久化业务 Task=FAILED）；
- 缺失/损坏/跨 Scope → fail-closed（抛异常）；
- 重复 resume → 新 attemptNo（不宣称由 Adapter 持久化旧 Attempt）；
- 不误删 Session；清理归独立生命周期服务。

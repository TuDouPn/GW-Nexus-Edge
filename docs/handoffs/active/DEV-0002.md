## 4. 设计与不变量

- 调用链：同一 Spring Boot 应用上下文（装配 DataSource/MyBatis-Plus/Sa-Token/Redis/Flyway/AgentScope）→ 官方 Starter/驱动 → 真实数据库/Redis（Testcontainers 固定版本镜像）→ 基础事务/迁移/认证语义断言。
- 不变量：**依赖证据来源统一规则**——开源依赖优先来自 Maven Central；DM8 等商业组件允许来自厂商官方渠道或企业批准的私有制品库；所有非 Maven Central 依赖必须记录来源、Maven 坐标、版本、SHA-256、许可证和获取方式；**兼容结论必须同时具备真实运行日志**。版本冻结必须经 ADR-0007；结论只区分「通过 / PARTIAL / BLOCKED」并给出证据；**不以 Context 启动成功代替功能兼容**（每项均为真实 API 行为断言）。
- 版本选择规则（评审项 5）：
  1. Spring Boot BOM 优先（mysql/postgresql/redis/flyway 等由 SB 4.1.0 BOM 管理，不另定版本）；
  2. 官方 Spring Boot 4 Starter 优先（MyBatis-Plus/Sa-Token 的 SB4 Starter 存在则优先；若官方未提供 SB4 Starter，如实记录 BLOCKED/PARTIAL，**不降级 SB、不借用 SB3 Starter 冒充 SB4 兼容**）；
  3. 不以「最新版本」作为选择依据，以「BOM 管理 + 官方 SB4 Starter + 兼容测试证据」为准；
  4. 覆盖 BOM 版本必须有明确兼容原因和测试证据，记录于报告与 ADR-0007；
  5. ADR-0007 记录精确版本、传递依赖、排除项、许可证、已知 CVE 和升级风险。
- Schema/API/Event/State 影响：无业务 Schema、API、事件或状态机；仅 compat 模块 test 夹具迁移（验证 Flyway 能力，非业务 Schema）。

## 10. DM8 策略（评审项 3）

### 10.1 证据来源与 Maven 制品供应契约

1. **证据来源统一规则**：开源依赖优先来自 Maven Central；DM8 等商业组件允许来自**厂商官方渠道或企业批准的私有制品库**（证据来源规则见 §4 不变量）。
2. **生产与 CI**：优先从企业 Nexus/Artifactory 等**受控私有 Maven Repository** 解析 DM8 官方驱动（固定 Maven 坐标）。
3. **本地兼容测试**：允许将**合法获得的官方驱动**安装到受控本地 Maven Repository，但必须使用**固定坐标**并**验证 SHA-256**。
4. **POM 只引用 Maven 坐标**：禁止 `systemPath`、禁止绝对文件路径、禁止把商业驱动提交 Git。
5. **仓库地址与凭证**：通过 `settings.xml`、环境或 Secret Provider 注入，**不写入 POM 和仓库**。
6. **Compatibility Report 记录**：DM8 官方版本、Maven 坐标、来源及 SHA-256 映射。
7. **无合法驱动或私有制品来源时**：DM8 保持 **BLOCKED**，G-02 不得 PASS（见 §13）。

### 10.2 验证执行策略

1. **独立 Maven Profile**：DM8 相关依赖与测试置于独立 Profile（如 `-P dm8-compat`），默认构建不加载。
2. **默认 `clean verify` 在无 DM8 驱动时仍可执行**（DM8 测试位于 Profile 内，默认跳过；跳过不视为通过）。
3. **DM8 专用验证通过受控命令显式运行**（命令记录于报告，如 `./mvnw -P dm8-compat -pl nexus-edge-compatibility-test test`）。
4. **DM8 缺失或未完成真实验证时，G-02 最终状态只能是 PARTIAL，不能 PASS**（见 §13）。

## 11. Compatibility Harness 不进生产制品（评审项 4）

- 使用独立 **`nexus-edge-compatibility-test`** 模块（test 性质模块）。
- 不进入 Nexus Edge 生产镜像和运行时依赖：不加入生产模块依赖，生产构建/制品不受影响。
- MySQL、PostgreSQL、Redis、DM8 采用**独立 Test Slice/Profile**（各自 `@SpringBootTest` + 专属 Profile/配置），**避免多数据源自动配置互相污染测试结果**（如多 DataSourceAutoConfiguration 竞争、错误数据源注入）。

## 12. 版本选择规则（评审项 5）

1. Spring Boot BOM 优先（SB 4.1.0 BOM 已管理的依赖不另定版本）；
2. 官方 Spring Boot 4 Starter 优先；
3. 不以「最新版本」作为选择依据；
4. 覆盖 BOM 必须有明确兼容原因和测试证据（记录于报告与 ADR）；
5. ADR-0007 记录：精确版本、传递依赖、排除项、许可证、已知 CVE、升级风险。

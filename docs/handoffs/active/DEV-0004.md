## 1. 目标

核验 AgentScope Java 2.0.1 官方 Recovery（Checkpoint 相关）能力的真实 API、持久化语义、恢复语义与
Nexus Edge 集成边界，完成 G-03 剩余 Checkpoint 能力盘点。**不得把以下概念混为一谈**：
RedisAgentStateStore 的 Session/Agent State 持久化、AgentScope Execution Checkpoint、
Harness Workspace/Sandbox Snapshot、Nexus Edge MySQL Task/TaskAttempt 权威状态、
Coding Workspace 的 Git Commit/Patch/Artifact、Sandbox 容器生命周期。

## 2. 官方能力实证（设计评审 CHANGES_REQUESTED 修订）

### 2.1 统一结论表述（修正"Checkpoint 不存在"的逻辑跳跃）

> **AgentScope Java 2.0.1 未发现独立公开的 Execution Checkpoint API。**
> 官方恢复能力由 **AgentStateStore、AgentState、优雅中断状态、SandboxSnapshot 和 DistributedStore**
> 组合提供。**模型 Token、当前 Tool 调用栈、任意进程崩溃点的精确续跑未被证明，不属于 V1 承诺。**

不得再以"没有名为 Checkpoint 的类/接口"直接推导 AgentScope 没有恢复能力——恢复能力是上述组件组合。

### 2.2 能力分级（必须拆开，逐项定级）

| 能力项 | 判定 | 说明 |
|---|---|---|
| 跨 call 的 AgentState 恢复 | **VERIFIED / 待补官方源码证据** | AgentStateStore 同 scoped 身份 + store 重建恢复会话（DEV-0003 C-2 真实 Redis 已验证）；实现阶段补官方 sources 证据 |
| 优雅 interrupt 后保存部分状态 | **待实证** | ReActAgent `interrupt(ctx)` 存在（javap 实证）；中断后哪些状态被保存、下一 call 行为待可复现实验 |
| `shutdownInterrupted` 持久化语义 | **待实证** | 需在实现阶段实证该 API 是否存在、是否持久化及其恢复语义 |
| Sandbox 文件系统跨 call 恢复 | **待实证** | `SandboxSnapshot.persist/restore`（javap 实证接口）；Local/Remote 真实行为待实验 |
| 任意崩溃点精确续跑 | **NOT_SUPPORTED 或 NOT_VERIFIED** | 无官方 API 支持进程崩溃点精确续跑；按未证明对待 |
| Token 级断点续跑 | **NOT_SUPPORTED** | 不属于 V1 承诺（03 §6：业务步骤级恢复，不要求 Token 级续跑） |
| Nexus 业务步骤级恢复 | **Nexus 职责（不属于 AgentScope Checkpoint API）** | Nexus Task/TaskAttempt（MySQL 权威）+ AgentStateStore 会话恢复组合 |

## 3. 设计问题回答（VERIFIED / INFERRED / NOT_SUPPORTED / BLOCKED 分列）

1. 是否提供官方 Checkpoint？→ **未发现独立公开 Execution Checkpoint API（VERIFIED，闭包扫描）**；
   恢复能力为组件组合（§2.2）。
2. Artifact/类/接口/sources？→ §2.3 坐标；类见 §2.2/§2.4；官方 sources jar（Maven Central）实现阶段核验。
3. 保存内容？→ AgentState（会话/状态，JSON，AgentStateStore）；SandboxSnapshot（沙箱文件系统流）；
   非 Workflow 编排/Tool 内部状态/Token 进度（待实证确认边界，当前按未证明对待）。
4. 跨进程/实例/重启恢复？→ AgentStateStore 跨实例会话恢复已验证（DEV-0003 C-2）；SandboxSnapshot
   待实证；任意崩溃点/Tool 栈/Token 续跑 NOT_SUPPORTED/NOT_VERIFIED。
5. 持久化后端？→ AgentStateStore：任意实现（JsonFile/Redis…）；SandboxSnapshot：Local/Remote（Redis 等）。
6. 与 RedisAgentStateStore 区别？→ 会话/Agent State 持久化 vs 沙箱文件系统快照，数据面隔离（CP-7 实证）。
7. 经营分析需要？→ **不需要沙箱快照**（本地 HarnessAgent + 会话恢复足够，业务步骤级）；
   不得以"没有 Checkpoint 类"跳过对 AgentState 恢复的确认（§2.2 已拆解）。
8. Coding 需要？→ **修正（评审 CHANGES_REQUESTED）**：Coding 权威恢复 = 新 Sandbox + 不可变 Base Commit +
   Hash 校验的 Commit/Patch/ChangeSet 重放（22 §6）；**SandboxSnapshot 只是同一 Attempt 内跨 call 的性能
   优化和工作区延续能力，不是代码权威源、业务恢复权威源或 Production Artifact**；不得让 RedisSnapshot
   保存大型 Node Workspace 成为 V1 默认架构。
9. Nexus 保存哪些？→ MySQL 权威：Task/TaskAttempt/状态/恢复授权/关联标识（scope 四字段）；
   AgentState/沙箱快照/分布式执行状态归 AgentScope；Nexus 不复制 AgentScope 状态机/沙箱生命周期。
10. 官方不足 fail-closed？→ NOT_SUPPORTED/NOT_VERIFIED 如实标记；**禁止 Nexus 自研第二套 Agent Checkpoint
    Runtime**；恢复退化为业务步骤级（AgentStateStore 会话恢复）；走 ADR-0009 边界。

### 4.1 唯一实现复审定点修正（CHANGES_REQUESTED，已落实）

1. **CP-5/CP-6 证据等级**：结论改为 **"Local/Redis SandboxSnapshot payload persistence round-trip VERIFIED"**；
   **"完整 Sandbox 文件系统跨 call 自动恢复 NOT_VERIFIED"**（未启动真实 Sandbox/未验证 Sandbox Manager
   自动恢复）；测试方法/DisplayName/注释同步（payload 字节流，非"真实 tar 工作区归档"）；不新增 Docker
   Sandbox 集成测试（避免扩到 G-09）。
2. **CP-3 归因**：报告明确"优雅 **session interrupt** 后 call 结束时 AgentState 已持久化、下一 call 可恢复
   上下文：VERIFIED"；**不归因 bindStateSaver（process graceful shutdown 路径，无调用证据）**；进程 shutdown
   自动恢复 NOT_VERIFIED；shutdownInterrupted 仅字段持久化 VERIFIED。
3. **CP-7 双向隔离**：方向 A 删除 Snapshot 后经**官方 AgentStateStore 真实读取** AgentState 含 Marker；
   方向 B 重新 persist 后删除 AgentState，Snapshot 仍 isRestorable 且 restore 内容/Hash 一致；
   不依赖"已经为空"证明；Redis KEYS/DEL 仅测试黑盒观察，非生产契约（报告注明）。
4. **测试资源生命周期**：CP-6/CP-7 的 JedisPooled 经 try-with-resources 关闭（无连接泄漏）。
5. **CP-8 收紧**：Tool 栈/任意崩溃点/Token 级——官方未明确"不支持" → 统一技术事实 **NOT_VERIFIED**，
   另设 **V1 产品承诺列（OUT_OF_SCOPE / NOT_COMMITTED）**；不得用"不属于 V1 承诺"反推官方能力 NOT_SUPPORTED。
6. **ADR-0009**：验证与未解决问题更新为本次实际结果（7 项分列）；保持 **Proposed**；未改
   Blueprint/00_DECISIONS/ADR-0008/G-03/OQ-007。

## 1. 目标

核验 AgentScope Java 2.0.1 **官方 Checkpoint 能力**的真实 API、持久化语义、恢复语义与 Nexus Edge
集成边界，完成 G-03 剩余 Checkpoint 能力盘点。**不得把以下概念混为一谈**：

## 2. 官方能力实证（Maven jar/javap 扫描，2026-08-12；非猜类名）

### 2.1 VERIFIED 事实（jar 扫描）

| 事实 | 证据 |
|---|---|
| **AgentScope 2.0.1 无命名为 "Checkpoint" 的官方类/接口** | `agentscope-core`/`agentscope-harness`/全部 `agentscope-*` 扩展 jar 全量扫描：`find -iname "*checkpoint*"` 为空 |
| 持久化/恢复三件套 | `AgentStateStore`（core，会话/Agent State，DEV-0003 Redis 已验证）；`io.agentscope.harness.agent.sandbox.snapshot.*`（沙箱快照）；`DistributedStore`（远程执行组合） |
| **SandboxSnapshot 接口语义 = 沙箱文件系统快照（流式 persist/restore）** | `SandboxSnapshot`：`persist(InputStream)`/`restore()`/`isRestorable()`/`getId()`/`getType()`；`SandboxSnapshotSpec.build(String)`；`RemoteSnapshotSpec(RemoteSnapshotClient)` |
| SandboxSnapshot 实现 | `LocalSandboxSnapshot/LocalSnapshotSpec`、`RemoteSandboxSnapshot/RemoteSnapshotSpec`、`NoopSandboxSnapshot/NoopSnapshotSpec`（harness） |
| Redis 远程快照实现存在 | `RedisSnapshotSpec`/`RedisRemoteSnapshotClient`（agentscope-extensions-redis，DEV-0003 已 javap；**真实 persist/restore 行为未验证**） |
| HarnessAgent 恢复相关 | `workspaceFor(userId, sessionId)`、`getDistributedStore()`、`getAgentState(ctx)`；ReActAgent `interrupt(...)`/`getAgentState(...)`——无独立 Execution Checkpoint API |
| 跨实例会话恢复（已验证） | AgentStateStore 同 scoped 身份 + store 重建恢复会话（DEV-0003 C-2，真实 Redis） |

### 2.2 判定（对应设计问题 1~5，待实现阶段以可复现实验最终定级）

1. **AgentScope 2.0.1 是否提供官方 Checkpoint？** → **NOT_SUPPORTED（以 "Checkpoint" 命名的执行进度 Checkpoint API 不存在）**；
   恢复能力 = AgentStateStore（会话/Agent State）+ SandboxSnapshot（沙箱快照）+ DistributedStore。
2. **Artifact/类/接口/源码位置？** → 见 §2.1 证据表（agentscope-core：AgentStateStore；agentscope-harness：sandbox.snapshot.*、DistributedStore；agentscope-extensions-redis：RedisAgentStateStore、RedisSnapshotSpec/RedisRemoteSnapshotClient）。官方 sources jar 可下载核验（DEV-0003 已用同法）。
3. **Checkpoint 保存什么？** → 无统一 "Checkpoint"。AgentStateStore 保存 AgentState（会话消息/状态，JSON）；SandboxSnapshot 保存**沙箱文件系统**（persist/restore 流）；**不包含** Workflow 编排状态/Tool 内部状态/Token 级执行进度（待实验确认边界，当前按 NOT_SUPPORTED 对待）。
4. **跨进程/实例/重启恢复？** → AgentStateStore：支持（同 scoped 身份重建，DEV-0003 C-2 验证）；SandboxSnapshot：接口设计支持（persist 后可 restore），**真实行为待可复现实验验证（INFERRED）**；无"当前执行续跑"（Token 级）——03 §6 明确 V1 只需业务步骤级恢复。
5. **持久化后端？** → AgentStateStore：任意实现（JsonFile/Redis/…）；SandboxSnapshot：Local（本地）或 Remote（RemoteSnapshotClient，如 Redis）。

## 3. 设计问题 6~10 回答（区分 VERIFIED / INFERRED / NOT_SUPPORTED / BLOCKED）

6. **与 RedisAgentStateStore 区别？**（VERIFIED，jar 实证）
   - RedisAgentStateStore：**会话/Agent State 持久化**，键 `{prefix}{userId}/{sessionId}:{key}`（scoped 分区），JSON 值，供会话恢复与执行上下文投影（DEV-0003）。
   - SandboxSnapshot：**沙箱文件系统快照**，`persist(InputStream)/restore()` 流式，供沙箱生命周期（挂起/恢复工作区文件系统）；与会话状态完全不同的数据面。
   - 两者**不得混用**：会话恢复 ≠ 沙箱快照恢复。
7. **经营分析 Workspace 是否需要它？**（推断：不需要；待实验确认）
   - 经营分析使用本地 HarnessAgent + AgentStateStore 会话恢复即可（业务步骤级恢复，03 §6）；无沙箱文件系统恢复需求 → **SandboxSnapshot 不纳入**。
8. **Coding Workspace 是否需要它？**（推断：需要，但属 Coding 工作项）
   - Coding 远程 Sandbox 挂起/恢复需要 SandboxSnapshot + DistributedStore（远程文件系统/消息总线）；该验证属 Coding Workspace 工作项，DEV-0004 只盘点 API 边界，**不实现 Coding Sandbox**。
9. **Nexus 保存哪些业务关联？**（VERIFIED/设计）
   - Nexus（MySQL 权威）：Task、TaskAttempt、状态、恢复授权、关联标识（taskId/taskAttemptId/agentId/traceId + tenant/workspace/user/session scope）。
   - AgentScope 管理：AgentState（会话）、沙箱快照、分布式执行状态。
   - Nexus **不复制** AgentScope 状态机/沙箱生命周期。
10. **官方不足时 fail-closed？**（设计）
    - 若某恢复能力 NOT_SUPPORTED（如 Token 级执行 Checkpoint）：**不自行实现第二套 Agent Checkpoint Runtime**；
      标记 NOT_SUPPORTED/BLOCKED，走 Open Question / 新 ADR；恢复退化为业务步骤级（AgentStateStore 会话恢复）。
